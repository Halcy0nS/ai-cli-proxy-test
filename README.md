# AI CLI 代理节点测试 Skill

把一次工具开发中的方法和踩坑经验交给 AI，让它针对接收者的电脑重新开发、适配并验证。

这个 Skill 帮助 AI 构建逐节点测试工具：发起真实模型推理，确认请求经过目标代理节点，并区分地区拒绝、网络失败、登录问题和额度限制。默认采用独立临时代理，尽量不干扰正在使用的客户端。

## 怎么使用

把仓库地址发给你的 AI，并附上：

```text
请读取这个仓库的 SKILL.md，并按需读取 references 中的适配资料。
我的代理客户端是「填写客户端」，要测试的 AI CLI 是「填写 CLI」。
先检查我的本机环境，再开发适合我的节点测试工具。
默认采用旁路测试，不重启或修改正在使用的代理 App。
用真实请求和代理路径证据验收，明确说明未验证的部分。
```

如果你的 Agent 支持安装 Skill，可将整个仓库作为 `ai-cli-proxy-test` 技能目录导入。保留 `references/`，只复制入口文件会丢失适配经验。也可直接下载仓库 ZIP，让 AI 读取文件。

## 内容

- [SKILL.md](SKILL.md)：环境发现、独立测试路径、真实推理和交付流程。
- [TNTCloud Lite 参考](references/tntcloud-lite.md)：加密配置与定制 IPC 的历史适配经验。
- [Clash Party 参考](references/clash-party.md)：标准 Mihomo 配置适配，以及第二次开发发现的问题。
- [验收参考](references/verification.md)：成功判定、路径证据、错误分类与清理测试。

仓库维护可复用的方法和适配经验。具体脚本由接收方 AI 根据本机环境构建，仓库不附带通用客户端程序。

## 如何形成

先从 TNTCloud Lite + agy 的构建记录提取初版，再用初版适配 Clash Party，最后把实际发现的问题反馈进 Skill：

- 模型列表返回不代表真实推理可用。
- 复制 direct 模式配置后，切节点也可能仍然直连。
- 订阅信息可能伪装成普通代理节点。
- 登录等待不应记成节点超时。
- 遥测和更新连接不能证明推理流量的路径。
- 推理服务主机可能随 CLI 版本变化。
- HTTP 资格检查的 EOF 不等于账号资格被拒绝。

## 验证范围

截至 2026-10-19，本机适配环境为 macOS arm64、Clash Party 1.9.5、Mihomo v1.19.24。生成工具的 16 项行为检查通过，包括真实内核配合模拟 CLI 的启动失败、超时、中断和清理检查；这些测试工具不包含在本仓库内。

登录后的真实抽样覆盖 7 个不同节点：5 个服务地区拒绝、1 个超时、1 个 HTTP EOF，0 个成功回复。6 个样本采集到推理主机经过目标节点的连接证据。**真实负例路径已验证，成功回复路径仍缺真实正例。** 不能据此判断整个客户端或所有节点不可用。

TNT 参考来自历史构建记录，本轮没有重新运行 TNT 内核。其他系统、客户端版本、provider、链式代理等需要重新适配。这里不提供当前可用节点清单，也不保证某个节点持续可用。

## 维护方式

遇到新环境时，让 AI 按 Skill 适配并验证；将实际改变决策的发现补进对应参考。更新应说明证据和验证范围，避免把一次机器上的实现写成通用规则。

公开内容不包含个人配置、订阅链接、节点凭据、授权码、原始日志、第三方二进制或提取的解密常量。
