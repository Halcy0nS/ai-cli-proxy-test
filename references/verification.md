# 验收：成功回答与正确路径缺一不可

## 一次结果的最小记录

记录时间、CLI/内核版本或指纹、配置来源及修改时间、模型、节点标识、最终状态、耗时、推理路径证据、清理结果。配置指纹只能证明文件是否变化，不能证明进程的全部内存状态。

使用短小、确定的提示词，例如要求只回答 OK。解析当前 CLI 的结构化最终结果，核对退出码和回答；不能把 step_update、stderr 中出现 OK 或模型列表当成成功。早先成功事件后出现失败，以最终状态为准。

路径证据至少关联独立测试实例、CLI 进程（PID 或可执行文件及独占实例上下文）、推理目标主机和选中节点。观察到更新、遥测或 OAuth 主机只能证明部分 CLI 流量。若域名变化，用当前实现/日志发现新主机并验证，不能放宽成“任意 googleapis.com”。

公开报告脱敏。控制 secret、OAuth 内容、节点 UUID/密码、订阅 URL、完整配置和原始 CLI 日志不进入报告。

## 分类和停止条件

| 状态 | 处理 |
| --- | --- |
| 完整成功且路径可证 | 记录当次可用 |
| 成功但路径缺证 | 记录未验证；补采证据 |
| 服务返回不支持地区 | 记录服务拒绝，可换节点；不推断真实地理位置 |
| 网络失败或时间预算耗尽 | 记录阶段和耗时，不推断地区限制 |
| 登录/鉴权失败 | 停止扫描，用户完成登录后重试 |
| 额度/限流 | 停止或按服务提示有界等待，避免连续消耗请求 |
| 模型不可用 | 核对账号可用模型后重试 |
| 内核/配置/沙箱失败 | 环境错误，尚未测到节点 |
| CLI 无最终事件或格式未知 | 未完成或解析器待适配 |

真实负例可以验证请求路径与失败分类；成功回复路径仍需真实正例。若抽样均失败，分开交付工具的已验证能力与节点结果，不据此断定整个客户端不可用，也不靠无限扩扫弥补证据。

区分“遍历结束”和“端到端验收通过”；全部失败也可能遍历结束。全量只指明确列出的候选集合。单次延迟包含 CLI 启动与服务调度，不能宣称最快节点长期最优。

## 行为测试

- 正常结束后进程、监听、临时配置已清理，原配置与系统代理未变。
- 内核启动失败、端口冲突、配置错误发生在正式测试前，也要清理。
- CLI 超时、登录等待和 Ctrl+C：子进程及其子进程退出，原状态恢复，部分结果保存。
- 部分文字、非零退出、最终失败、遥测连接：均不得误判成功。
- API 恰好有另一实例响应：随机 secret、唯一组和自有进程状态应阻止误操作。

真实内核 + 假 CLI 可证明生命周期管理；真实 CLI + 完整回答 + 推理链路才证明端到端。测试未覆盖的分支如 SIGKILL/断电、provider 和其他平台明确列为边界。
