# TNTCloud Lite / agy 适配记录

证据：2026-10-19 构建对话导出与现存脚本审查；历史运行结果不表示当前节点状态。本记录不附个人配置、节点 IP、第三方密钥或内核。

该安装使用定制 Mihomo 内核。磁盘配置不是普通 YAML，历史实现先解开 XOR/Base64 包装，再使用 AES-256-GCM 验证并解密。常量及算法必须针对本机版本核对；不要照抄未知来源的密钥。可导出配置时优先用导出。

历史参考的具体布局：以本机版本的 secret 分别连接 NUL 字节加 `cfg-xor-v1`、`cfg-disk-v1` 后做 SHA-256，派生 XOR 包装密钥与磁盘 AES 密钥。先逐字节循环 XOR，再 Base64 解码；前 12 字节为 nonce，末 16 字节为认证 tag，中间为密文。仅在 GCM 验证成功后解析配置。此处保留布局，省略提取的 secret；不能猜常量或在校验失败时继续。

定制内核不一定支持普通 Mihomo 命令行。该实例使用 Unix Socket：四字节 little-endian JSON 字节长度加 UTF-8 JSON 载荷；连接后依序请求 initClash（home-dir、version）、setupConfig（selected-map、test-url）、startListener。每一步应检查返回状态。原脚本只有部分状态验证，不应原样沿用。

参考请求形状为 `{id, method, arguments}`；历史成功调用以 `version: 1` 初始化，设置空 selected-map，再启动监听。Socket 流需处理分片/粘包并限制帧长。原记录还遇到参数缺失；二进制包含方法名并不等于协议已验证。使用本机 App 的内核时，应保持原文件不变；历史脚本曾提取匹配架构的普通权限副本供临时进程使用，是否需要此步骤由当前可执行权限与启动方式决定。

历史测试显示：模型列表返回和真实推理成功是两件事，部分节点仅在 agy -p 时返回地区拒绝。地区拒绝不能据此解释为出口实际在某国。

原实现值得修正的点：发现本地控制端口后自动切换到直接控制；删除现有连接；恢复节点不在 finally；明文临时配置未删除；固定端口和网卡；公共延迟失败跳过推理；收到部分文字就判成功。把这些当作验收反例。

启动顺序和加密流程只在历史记录所对应的安装上验证；没有证据支持所有 TNTCloud Lite 版本。分享包不分发第三方二进制或提取的解密常量，尚未核查这些内容的公开范围。
